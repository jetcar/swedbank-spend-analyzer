# Локальный доступ и белый список исходящих запросов

Приложение предназначено для одного пользователя на доверенном компьютере.
Пароля входа в UI/MCP и таймера локальной сессии нет.

## Схема

```text
Браузер -> 127.0.0.1:8000 -> gateway (Nginx) -> app -> postgres
MCP-клиент -> 127.0.0.1:8001/mcp -> gateway -> mcp -> app
app -> bank-egress (Nginx) -> https://api.enablebanking.com:443
```

- `app`, `mcp`, `postgres` подключены только к сети `private` с `internal: true`.
  Порты этих контейнеров не публикуются. У приложения и MCP удалены capabilities,
  файловая система доступна только для чтения, кроме временного каталога.
- `gateway` публикует только IPv4 loopback-порты 8000 и 8001. Он использует отдельную
  сеть `ingress`, поскольку в используемом Docker публикация портов контейнера,
  подключённого только к internal-сети, не работает. Его upstream фиксирован:
  только app и mcp, произвольные назначения и CONNECT не поддерживаются.
- Только `bank-egress` подключён к сети `internet` и проксирует банковские запросы.
  Конфигурация примонтирована только для чтения. Контейнер не публикует порты хоста.
- Для app, mcp, postgres и gateway внешний DNS отключён через `dns: [127.0.0.1]`.
  Внутренние имена Docker продолжают разрешаться. Это закрывает обход ограничения
  через пересылку внешних DNS-запросов встроенным DNS Docker.

## Исходящий белый список

Единственный upstream — `api.enablebanking.com`, HTTPS с проверкой сертификата и SNI.
Hostname назначения не берётся из клиентского Host, пути или параметров запроса.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/auth` | Начать банковскую авторизацию |
| POST | `/sessions` | Обменять одноразовый код на банковскую сессию |
| GET | `/accounts/{id}/transactions` | Прочитать операции, включая страницы по continuation_key |

Остальные пути и методы получают 403. Прокси не следует внешним редиректам.
Идентификатор счёта ограничен латинскими буквами, цифрами и дефисом.
Параметры query разрешены для пагинации и фильтра по дате.
Для новых банковских возможностей белый список нужно расширить явно.

В Compose `ENABLE_BANKING_API_URL` принудительно указывает на локальный прокси.
Перемена URL внутри приложения сама по себе не даёт внешнего доступа: запрет
прямого выхода действует на уровне Docker-сети.

## Веб-интерфейс

Gateway проверяет Host и Origin, запрещает cross-site обращения, кроме возврата
из банка на `/callback`. Проверка `state` в callback остаётся ответственностью backend.
MCP доступен без токена локальным клиентам по прежнему адресу.

Content-Security-Policy разрешает запросы, скрипты и ресурсы только со своего origin
(картинки также data:). Inline JavaScript и обработчики событий в HTML запрещены.
Скрипт интерфейса вынесен в `/static/app.js`; inline CSS пока разрешён для существующей
вёрстки. Заголовки отключают Referer, MIME sniffing и кэширование ответов.
Логи прокси не записывают query, тела запросов или Authorization; access log Uvicorn отключён.

Подтверждение доступа в Swedbank происходит в обычном браузере, который обращается
к банковским страницам напрямую. CSP приложения не является глобальным firewall
браузера и не ограничивает навигацию верхнего уровня, расширения и другие вкладки.

## Проверка

После запуска `docker compose up -d --build`:

```powershell
rtk python -m unittest discover -s tests -p test_network_security.py -v
$env:CHECK_BANK_EGRESS = '1'
rtk python -m unittest discover -s tests -p test_network_security.py -v
rtk npm test -- --run
```

Проверяются UI/БД, MCP initialize, loopback-публикация портов, Host/Origin,
callback, CSP, запрет прямых IPv4/IPv6 соединений и внешнего DNS из app/mcp,
запрещённые методы/пути прокси. Дополнительный сетевой тест отправляет запросы
без JWT к разрешённым банковским путям и ожидает 401 от upstream: реальные
авторизации и финансовые данные не создаются и не меняются.

При внедрении также выполнен read-only запрос операций с действующим ключом через
прокси: получен HTTP 200. Полный интерактивный вход в банк повторно не выполнялся.

## Границы защиты

Это ограничение сетевого доступа во время работы контейнеров, а не гарантия
безопасности любой библиотеки. Сами Nginx, Docker и хост входят в доверенную часть.
Разрешённые банковские запросы по определению могут содержать данные: белый список
ограничивает назначения и маршруты, но не доказывает безопасность каждого тела запроса.
Процесс с контролем Docker или хоста может изменить эти ограничения.
Локальные процессы пользователя могут обращаться к UI/MCP без пароля.

Загрузка образов и установка пакетов при сборке выполняются Docker на хосте и
не охватываются runtime-изоляцией. Приватный ключ и `.env` исключены из build context
через `.dockerignore`. Базовые образы закреплены digest; их обновление выполняется явно.
Обновление зависимостей и результаты сканирования описаны в [SECURITY-IMAGES.md](SECURITY-IMAGES.md).
Остальные обнаруженные при аудите вопросы (экранирование всех HTML-значений,
хранение OAuth state) требуют отдельных исправлений.

Источники: [Docker internal networks](https://docs.docker.com/reference/compose-file/networks/#internal),
[Docker DNS](https://docs.docker.com/engine/network/#dns-services),
[Nginx TLS upstream verification](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_ssl_verify).
