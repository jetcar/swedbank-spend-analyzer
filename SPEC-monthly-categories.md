# Spec: Monthly Category Management

## Objective

Добавить управление категориями по месяцам: категории текущего месяца создаются отдельно, автоматически копируются из предыдущего месяца, имеют бюджет и флаг активности. Удаление категории переносит операции этого месяца в «Без категории».

## Acceptance criteria

- Категория уникальна внутри месяца, но одинаковое имя может существовать в разных месяцах.
- При открытии месяца отсутствующие категории копируются из предыдущего месяца.
- Для категории можно изменить имя, бюджет и включить/выключить её. Имя редактируется в строке менеджмента категорий: Enter или выход из поля сохраняет, Escape отменяет. Пробелы по краям удаляются; имя должно содержать 1–100 символов и не повторять имя другой категории этого пользователя за тот же месяц. Ошибка сохранения возвращает прежнее имя и показывает сообщение. Переименование сохраняет ID, настройки и назначения операций; категории других месяцев не меняются.
- Каждая категория показывает месячные расходы, бюджет, остаток либо перерасход, процент использования и индикатор заполнения в обзоре и менеджменте категорий.
- Бюджет 0 означает «Без лимита»; процент и остаток для него не рассчитываются. При расходовании от 80% показывается предупреждение, при 100% — «Бюджет исчерпан», свыше 100% — перерасход.
- Отрицательный бюджет означает ожидаемый доход: `-1500` — план получить 1500 EUR. Создание, редактирование и копирование в следующий месяц сохраняют знак. Прогресс равен `earned / abs(budget)`, остаток — `abs(budget) - earned`; достижение и превышение плана отображаются как успех. Расходы не засчитываются в доход. Бюджет должен быть конечным числом.
- Поле `spent` в `GET /api/categories` суммирует все дебетовые операции выбранного месяца на отслеживаемых счетах, включая доли split без двойного учёта и без ограничения размера списка. Текущий формат бюджета и интерфейса — EUR, пересчёт валют не добавляется.
- Поле `earned` в `GET /api/categories` аналогично суммирует кредитовые операции (`CRDT`), включая доли split. При отсутствии поступлений возвращается 0; знак бюджета не меняет состав `spent` и `earned`.
- Изменения назначений, split, бюджета и мониторинга счетов обновляют состояние по существующей подписке SSE.
- Удаление категории отвязывает только операции соответствующего месяца.
- Основной список и группировка по дням используют категории выбранного месяца.
- Старые операции и существующие назначения сохраняются при миграции.

## Tech stack and commands

- FastAPI, SQLAlchemy async, PostgreSQL, vanilla HTML/CSS/JavaScript.
- `docker compose up -d --build`
- Проверка: `python -m unittest discover -s tests -v`

## Data model

`Category` получает `month` (`YYYY-MM`), `budget`, `enabled`; уникальность — `(name, month)`. `Transaction.category_id` продолжает ссылаться на месячную категорию.

`PATCH /api/categories/{id}` принимает необязательное `name`. Явно созданные или
переименованные категории отмечаются `name_customized`; их имена больше не заменяются
переводами стандартного набора. Флаг копируется вместе с категорией в следующий месяц.
При обновлении существующих схем столбец добавляется с `DEFAULT FALSE`, сохраняя данные.

## Testing strategy

- API smoke tests проверяют миграцию, копирование, настройки и удаление.
- UI regression test проверяет, что месячная категория появляется в выбранном месяце и удаление переносит операции в «Без категории».

## Boundaries

- Always: не менять операции других месяцев, сохранять существующие назначения, валидировать месяц и бюджет.
- Ask first: изменение формата операций или подключение нового внешнего сервиса.
- Never: удалять банковские операции или секреты.

## Open questions

Нет: бюджет хранится в валюте расходов месяца, выключенная категория скрывается из назначения, но её операции остаются видимыми.
